# 代码质量红线

所有条目为强制性约束，代码审查与静态扫描时逐项检查。

## 1. 复杂度与规模

| 指标 | 阈值 | 说明 |
|------|------|------|
| 圈复杂度 | ≤ 10 / 方法 | 超过则拆分私有方法或提前返回 |
| 认知复杂度 | ≤ 20 / 方法 | 关注嵌套、递归、多分支的心智负担 |
| 方法长度 | ≤ 100 行 | 超过则违反单一职责 |
| 文件长度 | < 600 行 | 无上帝文件，超过则拆类 |
| 方法参数 | ≤ 5 个 | 超出封装为 DTO |
| 嵌套层数 | ≤ 3 层 | Guard Clause 提前返回，减少 if/for 嵌套 |
| 类字段数 | ≤ 20 个 | 超过说明职责过多，应拆分 |

## 2. 重复代码

- 项目级重复代码率 ≤ 5%
- 三行以上相同逻辑必须抽取为方法
- 跨类重复的工具逻辑放 common 包

## 3. 注释纪律

**允许**：
- 描述业务意图和设计决策（WHY，不是 WHAT）
- 标注非显而易见的约束或权衡

**禁止**：
- 解释性注释（代码本身能说明的）
- BUG 修复追踪标记（`P0-`、`P1-`、`BUG修复`）
- 任务追踪注释（`TODO-xxx`、`FIXME` 超过一个迭代周期不处理）
- 兼容说明注释（`compat`、`为了兼容 xxx`）
- 重构记录注释（`重构前 xxx，现改为 xxx`）
- 注释掉的代码块（直接删除，git 有历史）

**方法注释**：所有 public 方法必须有 Javadoc —— 作用、核心逻辑、调用方。

## 4. 依赖方向

```
Controller → Service → Mapper
     ↓           ↓
   DTO/VO    Entity/DTO
```

- 上层依赖下层，**禁止反向依赖**
- 禁止循环依赖（A→B→A）
- Controller 禁止直接注入 Mapper
- 出参一律 VO，入参用 DTO，**Entity 禁止直出**
- 业务模块间协作走 Service 互调（当前为单模块，未来拆分时走领域事件 + SPI）

## 5. 单一职责

- 一个类只负责一件事
- 一个方法只做一步操作
- Service 不碰 HttpServletRequest/Response
- Controller 不写业务逻辑
- Mapper 不含业务判断

## 6. 修改纪律

- **不做历史兼容**：修改时直接改，不保留旧接口/旧字段/旧行为的兼容层
- **无用代码必须删除**：不保留注释掉的代码，不保留 `// removed` 标记
- **不做防御性冗余**：不为假想场景写 fallback，不为「以后可能用」保留废弃代码
- 删除代码不留痕迹，git history 就是记录

## 7. 禁止模式

| 禁止项 | 替代方案 |
|--------|----------|
| 空 catch 块 | 至少记日志 |
| 捕获 Exception 不处理 | 捕获具体异常或向上抛 |
| `System.out.println` | SLF4J + 占位符 |
| 循环内创建对象 | 提到循环外 |
| `==` 比较字符串 | `.equals()` |
| 修改参数引用 | 创建新对象返回 |
| `Executors.newFixedThreadPool()` | `ThreadPoolExecutor` 显式参数 |
| 魔法数字 | 命名常量（-1, 0, 1, 2, 10, 30, 60, 100, 1000 除外） |
| 星号导入 `import *` | 显式导入每个类 |
| N+1 查询 | 批量查询 / JOIN |
| 循环单条写库 | `saveBatch` |
| 大 OFFSET 深分页 | keyset 分页 |

## 8. 质量门禁

| 门禁 | 标准 |
|------|------|
| 后端构建 | `mvn clean compile` 零错误零警告 |
| 重复代码率 | ≤ 5% |
| 圈复杂度 | ≤ 10 / 方法 |
| 文件行数 | < 600 行 |
| 注释纪律 | 零禁止类注释 |
| 死代码 | 零死代码，无用代码必须删除 |
| 依赖方向 | 无反向/循环依赖 |
| 方法注释 | 所有 public 方法有 Javadoc |
