# 编码核心原则

Behavioral guidelines to reduce common LLM coding mistakes.

## 1. Think Before Coding

- 明确声明你的假设，不确定就问。
- 存在多种理解时，列出来而不是默默选一个。
- 存在更简单的方案时，说出来。
- 不清楚的地方，停下来，说明困惑点，提问。

## 2. Simplicity First

- 不添加未被要求的功能。
- 单次使用的代码不引入抽象。
- 不为假想的未来需求写「灵活」代码。
- 不为不可能发生的场景写错误处理。
- 200 行能用 50 行解决，就重写。

## 3. Surgical Changes

- 不「顺手改进」相邻代码。
- 不重构没坏的东西。
- 匹配现有风格，即使你会用不同方式。
- 只清理你自己造成的无用代码。

## 4. Goal-Driven Execution

将任务转化为可验证的目标：
- 「加校验」→ 写测试 → 通过
- 「修 bug」→ 写复现测试 → 通过
- 「重构 X」→ 前后测试都通过

多步任务先列计划：
```
1. [步骤] → 验证: [检查项]
2. [步骤] → 验证: [检查项]
```

## 5. Code Quality Constraints

详细红线见 [quality-guide.md](./quality-guide.md)，核心约束：

- 圈复杂度 ≤ 10 / 方法，认知复杂度 ≤ 20
- 重复代码率 ≤ 5%
- 文件 < 600 行，方法 ≤ 100 行，嵌套 ≤ 3 层
- 参数 ≤ 5，超出用 DTO
- 注释仅描述业务意图（WHY），禁止解释性/BUG修复/任务追踪/兼容说明/重构记录
- 所有 public 方法必须有 Javadoc
- 依赖方向自上而下，禁止反向/循环依赖
- 单一职责，一个类/方法一件事
- 零死代码，删除无用代码，不做历史兼容
- Guard Clause 优先，减少嵌套
- 禁止过度抽象：不引入不必要的接口/工厂/策略模式
