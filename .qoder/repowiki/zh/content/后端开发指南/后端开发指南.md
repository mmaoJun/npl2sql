## 简介
本指南面向有经验的 Java 开发者，系统性说明 NL2SQL 智能查询系统后端（Spring Boot）的架构、模块职责、实现原理、扩展方式以及开发与运维最佳实践。项目通过自然语言生成 SQL，结合多层安全校验、元数据缓存和多数据源适配器，提供稳定可控的只读查询能力；同时支持 Ollama 本地模型与 DashScope 云端模型的灵活切换。

## 项目结构
后端采用分层架构：控制器暴露 REST API，服务层编排 NL2SQL 流程，适配器对接不同数据库，安全组件负责认证与 SQL 安全检查，配置类集中管理基础设施行为。

## 架构总览
NL2SQL 的核心调用链从 ChatController 开始，经过 NL2SQLEngine 编排 Schema 获取、提示词构建、SQL 生成、安全校验、执行查询和审计记录；认证由 JwtAuthenticationFilter 前置校验，SQL 安全由 SqlSecurityChecker 进行关键词黑名单、AST 解析与注入检测；元数据通过 MetadataService 使用 Redis 缓存；多数据源通过 DataSourceFactory 与 BaseDataSourceAdapter/MySQLAdapter 接入。

```mermaid
sequenceDiagram
    participant FE as "前端"
    participant AuthC as "AuthController"
    participant ChatC as "ChatController"
    participant Eng as "NL2SQLEngine"
    participant MetaS as "MetadataService"
    participant Prom as "PromptBuilder"
    participant QClass as "QueryClassifier"
    participant PTmpl as "PromptTemplateService"
    participant SchComp as "SchemaCompressor"
    participant Gen as "SQLGenerator"
    participant Sec as "SqlSecurityChecker"
    participant DSF as "DataSourceFactory"
    participant Adapter as "BaseDataSourceAdapter/MySQLAdapter"
    participant Audit as "AuditService"
    participant DB as "业务数据库"
    participant Redis as "Redis"

    FE->>ChatC: POST /api/v1/chat
    ChatC->>Eng: processQuery(message, datasourceId, username)
    Eng->>MetaS: getSchema(datasourceId)
    MetaS->>Redis: 读取 schema 缓存
    alt 缓存命中
        Redis-->>MetaS: TableInfo[]
    else 缓存未命中
        MetaS->>DSF: getAdapter(...)
        DSF->>Adapter: getTables()
        Adapter->>DB: INFORMATION_SCHEMA 查询
        DB-->>Adapter: 表结构
        Adapter-->>MetaS: TableInfo[]
        MetaS->>Redis: 写入缓存
    end
    Eng->>Prom: build(nlInput, tables, dialect)
    Prom->>QClass: classify(nlInput)
    Prom->>PTmpl: getSystemPrompt(dialect)
    Prom->>SchComp: compress(tables, nlInput)
    Prom-->>Eng: promptText
    Eng->>Gen: generate(promptText)
    Gen-->>Eng: rawOutput -> extractSql()
    Eng->>Sec: validate(sql)
    alt 校验失败且允许重试
        Eng->>Prom: buildWithRetry(...)
        Eng->>Gen: generate(retryPrompt)
        Eng->>Sec: validate(sql)
    end
    Eng->>Sec: enforceLimit(sql, maxLimit)
    Eng->>DSF: getAdapter(datasourceId, type, config)
    Eng->>Adapter: executeQuery(sql, limit)
    Adapter->>DB: SELECT ... LIMIT N
    DB-->>Adapter: ResultSet
    Adapter-->>Eng: QueryResult
    Eng->>Audit: log(userId, datasourceId, nlInput, sql, ...)
    Eng-->>ChatC: ChatResponse
    ChatC-->>FE: ApiResponse<ChatResponse>
```

### NL2SQL 引擎与提示词工程
NL2SQLEngine 是核心编排器：获取 Schema、构建 Prompt、调用模型生成 SQL、安全校验、执行查询并记录审计。

```mermaid
flowchart TD
    Start(["进入 processQuery"]) --> LoadDS["加载数据源配置"]
    LoadDS --> GetSchema["获取 Schema（优先 Redis 缓存）"]
    GetSchema --> EmptySchema{"是否无表结构？"}
    EmptySchema -->|是| ThrowNoSchema["抛出 NO_SCHEMA_FOUND"]
    EmptySchema -->|否| BuildDialect["获取方言"]
    BuildDialect --> BuildPrompt["PromptBuilder.build(...)"]
    BuildPrompt --> GenerateSQL["SQLGenerator.generate(...)"]
    GenerateSQL --> CheckEmpty{"是否空结果或无法理解？"}
    CheckEmpty -->|是| ThrowGenFailed["抛出 SQL_GENERATION_FAILED"]
    CheckEmpty -->|否| Validate["SqlSecurityChecker.validate(...)"]
    Validate --> Valid{"是否通过？"}
    Valid -->|是| EnforceLimit["enforceLimit(...)"]
    Valid -->|否| RetryLoop["最多重试 maxRetry 次"]
    RetryLoop --> BuildRetry["PromptBuilder.buildWithRetry(...)"]
    BuildRetry --> GenerateRetry["SQLGenerator.generate(...)"]
    GenerateRetry --> Validate
    EnforceLimit --> Execute["Adapter.executeQuery(...)"]
    Execute --> Success{"是否成功？"}
    Success -->|否| ThrowExecFail["抛出 SQL_EXECUTION_FAILED"]
    Success -->|是| ReturnOK["返回 ChatResponse.success(...)"]
    ThrowNoSchema --> Audit["AuditService.log(...)"]
    ThrowGenFailed --> Audit
    ThrowExecFail --> Audit
    ReturnOK --> Audit
    Audit --> End(["结束"])
```

### 安全体系
- 认证：JwtAuthenticationFilter 从 Authorization 头提取 Bearer Token，JwtTokenProvider 生成/验证 JWT，SecurityConfig 禁用 CSRF、无状态会话、放行认证与文档接口。
- SQL 安全：SqlSecurityChecker 做关键词黑名单、AST 解析为 Select、堆叠查询/UNION 注入检测，并提供 enforceLimit 强制限制行数。

## 性能优化与安全加固

### 性能优化
- Schema 缓存：MetadataService 使用 Redis 缓存表结构，TTL 可通过 schema-cache.ttl-seconds 配置。
- 连接池：HikariCP 在 MySQLAdapter 中配置连接池参数；应用级数据库连接池在 application.yml 中配置。
- 模型输出截断：SQLGenerator.extractSql 去除 Markdown 代码块与多余分号，减少无效文本。
- 提示词压缩：SchemaCompressor 控制 Token 预算，避免过长上下文影响模型推理速度。
- 查询超时：MySQLAdapter.executeQuery 设置 Statement 查询超时，避免长事务拖慢服务。

## 常见问题排查
- 无法连接数据库：检查 host/port/databaseName/username/password；使用 DataSourceController 的测试连接接口验证。
- Schema 缓存异常：检查 Redis 连接与权限；使用 MetadataController 刷新接口重建缓存。
- 模型调用失败：确认 Ollama 或 DashScope 配置正确；必要时切换到另一个 provider。
- SQL 被拒绝：查看 SqlSecurityChecker 的错误信息；简化问题或调整表述以符合只读查询约束。
- 跨域问题：确认 WebConfig 允许的 Origin 包含前端地址。
